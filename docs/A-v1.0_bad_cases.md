# A-v1.0 公开版 Bad Cases 摘要

## 1. 未知设备型号误答

- 表现：用户输入仓库中不存在的设备型号时，系统容易从相似设备资料中给出看似合理但实际无依据的回答。
- 当前处理：优先进行设备型号一致性过滤，资料不足时直接拒答。
- 公开版保留策略：保留该防线，并在核心回归中验证未知型号拒答。

## 2. 高风险场景需要禁止直接操作

- 表现：UPS 电池冒烟、异味等问题如果只按一般问答输出，存在误导风险。
- 当前处理：回答层增加安全提示，工单层进入 `NEED_HUMAN` 并等待人工确认。
- 公开版保留策略：保留，并纳入发布场景测试。

## 3. 同型号多资料时引用不稳定

- 表现：同一设备型号存在维护手册和故障手册时，引用结果可能落到相关但不够“最具体”的文档。
- 当前处理：在检索后处理里增加型号与故障码 specificity 排序。
- 公开版保留策略：保留，并用发布场景测试固定主行为。

## 4. 外部增强能力受环境影响

- 表现：真实 Milvus、Neo4j、MinerU、Vision LLM 的联通性高度依赖本地环境和凭证。
- 当前处理：默认关闭，未配置时退回本地可跑模式。
- 公开版保留策略：代码保留，文档说明为可选增强，不进入默认 CI。

## 总结

公开版 bad cases 的目标不是展示所有研发细节，而是突出三个真实工程风险：

- 检索错配
- 高风险误导
- 外部依赖不稳定

这三类问题都已在当前公开版策略中有对应的收敛手段。
