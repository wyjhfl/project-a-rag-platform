# A-v1.1 面试讲法与版本边界说明

## 1. 一句话讲法

Project A 是一个企业设备售后诊断 RAG 平台，重点不是问答本身，而是把“故障描述 -> 检索诊断 -> 引用证据 -> 工单推进”做成可运行、可验证、可复现的业务闭环。

## 2. 建议默认讲法

### 2.1 主链怎么讲

推荐顺序：

1. 资料进入统一入库链路。
2. 问题进入检索增强和安全检查链路。
3. 返回答案时必须带引用和资料不足边界。
4. 高风险问题会进入工单流和人工确认。
5. 前端和 API 都可以演示这条链路。

建议表述：

> 这个项目默认能演示的是一条完整售后主链，不只是问答。  
> 用户描述设备故障后，系统会先做资料检索和安全判断，再给出带引用的诊断建议；如果是高风险问题，会进入 LangGraph 工单闭环，支持人工确认、恢复和关闭。

### 2.2 默认可跑能力怎么讲

可以明确说：

- 默认主链基于 `SQLite + Chroma + 脱敏资料 + FastAPI + Vue3`。
- 默认可验证文档入库、问答引用、多轮会话、工单闭环、评测入口和 Docker 化部署。
- 默认 CI 只覆盖公开主链，不依赖外部增强组件。

### 2.3 可选增强怎么讲

建议表述：

> Redis、PostgreSQL、Milvus、Neo4j 和真实多模态链路我都保留了代码入口，并且部分做了真实验收；但这些能力不作为公开仓库默认前提，而是按需接入的增强项。

这样讲的好处：

- 不夸大默认开箱能力。
- 仍然保留工程广度。
- 能自然引出“为什么要分默认链路和增强链路”。

## 3. 公开版和研发验证版的边界

公开版：

- 目标是可读、可跑、可验证。
- 强调核心业务闭环和主链稳定性。
- 不要求所有外部依赖默认开启。

研发验证版：

- 可以连接真实 Redis、PostgreSQL、Milvus、Neo4j、Vision LLM。
- 可以做更重的真实环境验收。
- 允许存在更多本地调试材料、预检记录和联调脚本。

不要混淆的点：

- “代码存在”不等于“默认开箱即用”。
- “有真实验收材料”不等于“已经纳入 CI 默认前提”。
- “设计文档里写过”不等于“当前公开版必须全部默认打开”。

## 4. 不要夸大的点

下面这些说法不建议直接对外说：

- 当前公开版已经完全按设计文档全部默认实现并默认可跑。
- 所有增强能力都不需要额外配置就能直接演示。
- 当前评测体系已经是完整官方 RAGAS 体系。
- 当前可观测性已经是完整 LangSmith / LangFuse 生产级追踪。

原因：

- 这些表述会把“增强能力”误说成“默认承诺”。
- 一旦被继续追问运行前提、凭证、环境和复现方式，风险很高。

## 5. 被追问时怎么解释

### 5.1 为什么不默认全开 Redis / PostgreSQL / Milvus / Neo4j

推荐回答：

> 我刻意把默认主链和增强链路分开了。公开仓库优先保证本地可复现和 CI 稳定，所以默认主链只依赖 SQLite 和 Chroma。  
> Redis、PostgreSQL、Milvus、Neo4j 我做成按需接入，是为了把工程扩展能力保留住，但不把外部环境复杂度强塞给每个使用者。

### 5.2 为什么前端不是设计文档里的 Streamlit

推荐回答：

> 设计文档早期预想的是 Streamlit，但后续演进成了 Vue3 企业工作台。这个变化不是功能缺失，而是更贴近企业演示和 API 协同的正向演化。  
> 我在发布文档里把这个技术路线变化明确写出来，避免继续沿用旧说法。

### 5.3 真实 LLM / 多模态是不是默认保证可用

推荐回答：

> 默认主链不把真实 LLM 和真实多模态当成公开仓库必须前提。  
> 我保留了这些入口，也做了预检和部分真实验收，但公开版强调的是“主链稳定 + 增强项按需接入”。

### 5.4 你怎么证明这不是只会讲故事

推荐回答：

> 我把每个核心能力都落成了代码入口、测试或验收材料和边界说明。  
> A-v1.1 专门做的就是这件事：让 README、发布审查、功能核对、API 说明和验证记录互相能对得上。

## 6. 面试时最稳的讲法模板

> Project A 的核心不是做一个问答 demo，而是做企业设备售后诊断的业务闭环。  
> 默认主链我保证用本地可复现方式跑通：资料入库、检索增强、带引用问答、安全边界、多轮指代、LangGraph 工单闭环、Vue3 工作台和核心测试。  
> Redis、PostgreSQL、Milvus、Neo4j 和真实多模态我都做成了可选增强，并保留了真实验收材料，但我不会把它们夸大成公开仓库默认开箱能力。  
> A-v1.1 的工作就是把这些边界和证据固定下来，让项目不仅能跑，还能被别人快速验证。
