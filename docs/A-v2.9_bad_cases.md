# A-v2.9 Bad Cases

## 本轮基线问题

扩容前旧报告暴露的问题集中在三类：

- `context_noise`：同设备资料命中，但混入相邻故障或其他设备 chunk。
- `answer_coverage_gap`：引用里有关键词，但抽取式回答没有完整说出。
- `grounding_gap`：中文 faithfulness 评测按空格切词时低估回答和上下文重合。

## 修复记录

### 1. 标题级故障码丢失

现象：

- `BAT-SMOKE`、`COM-08`、`UV-1` 等信息常出现在 Markdown 标题里。
- 原语义切片只把正文写入 chunk，导致引用上下文缺少标题里的故障码。

处理：

- `semantic_chunk_text` flush 时将当前 section 标题并入 chunk 内容。

结果：

- `context_recall` 提升到 `0.9778`。

### 2. 多字母故障码识别不足

现象：

- `UV-1`、`BAT-VOLT` 等故障码不稳定进入 Agentic specificity 排序。

处理：

- 扩展 Agentic 故障码正则，支持多字母前缀。
- 扩展售后意图词：欠压、输入电源、接触器、压差、单体电压、输出线、释放压力。

结果：

- 真实回归扩容到 30 条后全部通过。

### 3. 危险操作回答不够显式

现象：

- 某些危险问题能命中正确资料，但回答没有稳定覆盖“停机、检查、人工”等安全关键词。

处理：

- 安全 warning 固定包含禁止/不建议、停机或隔离、检查风险点、升级人工确认。

结果：

- 真实对抗扩容到 20 条后全部通过。

## 剩余观察

RAGAS 风格报告仍有 3 个低分 case：

- `real-reg-006`
- `real-reg-010`
- `real-reg-023`

这些 case 没有阻塞验收，原因是主验收指标已经达标，且回归/对抗均全量通过。后续如果继续优化，应优先做 answer coverage 的结构化模板，而不是继续堆检索策略。
